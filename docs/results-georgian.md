# Georgian results (our language)

Generated by `scripts/results_table.py ka` from the committed `runs/*/scores.json`; do not edit by hand.
WER/CER: corpus rates (%) under the declared policy `configs/scoring.yaml`; CI: 95% cluster bootstrap over speakers (CV) / sentences (FLEURS). Both fine-tunes trained on the official CV 27.0 ka train split (147.5 h, 139 speakers, speaker-disjoint from dev/test; `runs/train_*`); checkpoint chosen by dev WER; decoding identical to the corresponding baseline; test run once with frozen configs (baselines frozen in 0c0d0e4, rule for ours in the same commit, before any Georgian test run).

\* The NVIDIA model was trained on Common Voice 17.0 train/dev/other (model card), and `scripts/cv_contamination.py` shows it has seen many of these CV clips (WER 1.8-4.2% on older clip IDs, 23% on the newest). Its CV numbers are not a fair comparison; FLEURS ka test (held out by NVIDIA) is.

The MFCC + GMM-HMM rows are a classical baseline we trained from scratch (`recipes/kaldi-gmm-ka/`) on the same CV train split, on CPU. Unlike the neural baselines (greedy / beam decoding without an external LM) it decodes with a trigram LM built from CV train transcripts (no dev/test text; 0 raw verbatim dev/test sentences in train, 0.1% after normalization, `docs/split-audit.md`) and a closed 91k-word vocabulary (OOV: 5.6% of CV dev tokens, 14.8% of FLEURS dev). LM weight and insertion penalty were selected on CV dev (`recipes/kaldi-gmm-ka/decode-frozen.yaml`). Its output has no case or punctuation, so only normalized WER/CER apply. RTFx is wall clock on 8 parallel CPU decode jobs, MFCC extraction included.

"+ our word 3-gram LM" rows decode the CTC model with that same CV-train trigram (pyctcdecode + KenLM, beam 100). LM weight α and insertion bonus β were selected on dev by a rule committed beforehand (`scripts/lm_select.py`, `configs/runs/ka/mms-1b-all-kat-adapter-ft_cv-ka+lm-selection.yaml`: α 0.5, β 0), and the same pair is applied to MMS zero-shot as an ablation that separates the LM's gain from the fine-tune's. Our MMS fine-tune was rebuilt from the pinned base model + its backed-up adapter (`scripts/rebuild_mms_adapter.py`; 405/409 FLEURS dev hypotheses identical to the original greedy run).
